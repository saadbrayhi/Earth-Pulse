# EarthPulse: water changes, seen from space

NASA Space Apps Challenge 2026: *Dancing with the SARs*.

EarthPulse uses real **NASA–ISRO NISAR** L-band radar to show where water appeared or disappeared, and explains it in
plain language. Radar sees through clouds and at night: calm water looks dark, land looks bright.

Who it helps: farmers (when is my field dry enough to plant?), fishers, local officials and aid groups during floods,
and anyone who needs to know where water went when clouds block normal satellite photos.

The site has two parts:

- **Example: Tanguar Haor** (`/`): a ready-made, fully processed case study of a seasonal wetland in Bangladesh,
  28 Oct → 9 Nov 2026. It loads instantly and works without the server.
- **Check any place** (`/live`): click the map or search a place, then pick a 3–10 km box. EarthPulse searches NISAR for
  dates that can be compared fairly, reads **only that box** from the source files at the Alaska Satellite Facility, and
  returns the same water map and report in about 1–2 minutes.

Both show a **map** (date 1 / date 2 / what changed; click any spot to see "was it under water on each date?") with a
**report below**: key numbers, what the satellite saw, why it probably happened, other explanations, why it matters,
how sure we are, and a folded "for experts" section (histogram, thresholds, method, limitations, source files).
The report can be printed or saved as PDF.

## Architecture

```
Browser (Next.js, Leaflet)
  ├─ /        static example: public/data/tanguar-haor/*  (generated by scripts/process_change.py)
  └─ /live    calls the EarthPulse API ──► server/app.py (FastAPI)
                                             ├─ ASF search API          (which scenes cover the box?)
                                             ├─ NISAR .h5 at ASF        (HTTP range reads of the box only)
                                             └─ earthpulse/analysis.py  (same science as the example)
```

The Earthdata login stays on the server; it is never sent to the browser.

### Fair comparison rules

Two dates are only offered together when they share **orbit direction + track + frame** (same viewing angle),
**range bandwidth** (same sharpness / pixel size) and **product maturity** (validated vs provisional), and both fully
cover the box. Validated sets are suggested first.

For the Tanguar Haor example these rules leave exactly one pair that covers the whole area:

| Candidate pair | Validated | Same sharpness | Same orbit | Area covered |
| --- | --- | --- | --- | --- |
| **28 Oct → 9 Nov (track 69)** | ✅ | ✅ 40 MHz | ✅ | **100%** |
| 21 Oct → 2 Nov (track 141) | ✅ | ✅ 40 MHz | ✅ | ~51% |
| 30 Oct → 11 Nov (track 91) | ✅ | ❌ 40 vs 20 MHz | ✅ | 100% |
| 6 Oct → 30 Oct (track 91) | ❌ 6 Oct provisional | ✅ 40 MHz | ✅ | 100% |

### Method (short)

- Common UTM grid (if pixel sizes ever differ, the finer scene is averaged in linear power).
- Lee speckle filter (7×7 when pixels carry few looks, else 5×5); looks from the product's `numberOfLooks` layer.
- **Water-like** = HH below the dark-population mode + 1σ **and** HV within 2 dB of the HV noise floor (thresholds
  derived from the data; a fixed −15 dB HH threshold is used, and reported, when an area has almost no water).
- Classes: persistent / receded / new water-like; 3×3 majority clean-up; change patches < 0.25 ha ignored as speckle.
- Areas computed on the UTM grid; map layers reprojected to Web Mercator.
- The explanation text is generated by fixed rules from the measured numbers. Monsoon-specific wording is only used
  for the Tanguar Haor example; other places get neutral wording.

### Limitations

Low backscatter is consistent with open water but does not prove it (smooth mud, radar shadow). Wind can make water
look bright; water under plants is missed. Only two dates are compared and there is no ground truth. Each report lists
its own limitations.

## Run it locally

1. **Earthdata login** (https://urs.earthdata.nasa.gov, then authorize ASF data access once by downloading any small
   file on https://search.asf.alaska.edu). Put it in `~/.netrc`:
   ```
   machine urs.earthdata.nasa.gov
       login YOUR_USERNAME
       password YOUR_PASSWORD
   ```
   On a server use environment variables instead: `EARTHDATA_TOKEN`, or `EARTHDATA_USERNAME` + `EARTHDATA_PASSWORD`.
2. **Python** (3.11+):
   ```bash
   python -m venv .venv
   .venv/Scripts/python -m pip install -r scripts/requirements.txt   # Windows
   # .venv/bin/python -m pip install -r scripts/requirements.txt     # macOS / Linux
   ```
3. **Live API** (port 8000):
   ```bash
   .venv/Scripts/python -m uvicorn server.app:app --port 8000
   ```
4. **Website** (port 3000):
   ```bash
   npm install
   npm run dev
   ```
   The site calls `http://localhost:8000` by default; set `NEXT_PUBLIC_API_URL` to use a deployed API.

### API

| Endpoint | |
| --- | --- |
| `GET /api/health` | server status and which login method is configured |
| `GET /api/scenes?bbox=w,s,e,n` | comparable sets of NISAR dates for the box (max side 12 km) |
| `POST /api/analyze` `{bbox, before, after}` | starts a job, returns `{jobId}` (results are cached by box + scenes) |
| `GET /api/jobs/{jobId}` | progress log, then `result` = folder with layers + `metadata.json` |

Server options: `ALLOWED_ORIGINS` (CORS, default `*`), `EARTHPULSE_MAX_SIDE_KM` (default 12),
`EARTHPULSE_WORKERS` (default 2), `EARTHPULSE_CACHE` (default `server/cache`).

**Hosting tip:** NISAR data is stored in AWS `us-west-2`; running the API there makes the range reads much faster.

### Rebuild the Tanguar Haor example

```bash
.venv/Scripts/python scripts/search_gcov.py
.venv/Scripts/python scripts/fetch_subset.py --dates 2026-10-28 2026-11-09
.venv/Scripts/python scripts/process_change.py --before 20261028 --after 20261109
```

## Code map

| Path | Role |
| --- | --- |
| `earthpulse/remote.py` | Earthdata session + seekable HTTP range reader for `.h5` files |
| `earthpulse/subset.py` | read only a box from a remote GCOV file (+ QA summary) |
| `earthpulse/asf.py` | ASF search and "fair comparison" grouping |
| `earthpulse/analysis.py` | speckle filter, water rule, change classes, statistics, web layers, metadata |
| `server/app.py` | FastAPI live API (jobs, progress, cached results) |
| `scripts/*.py` | command-line pipeline for the example |
| `src/app/page.tsx`, `src/app/live/page.tsx` | example page and live tool page |
| `src/components/ResultView.tsx` | map on top + report below |
| `src/components/RadarMap.tsx` | result map with "is this spot under water?" click check |
| `src/components/Report.tsx` | the report |
| `src/components/LiveTool.tsx`, `SelectMap.tsx` | choose area + dates, run the live analysis |
| `src/lib/explain.ts` | rule-based plain-language explanation and confidence |
